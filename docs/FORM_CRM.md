# CRM-форма «Заявка на подбор хостинга»

## 1. Создание формы

**CRM → Продажи → Каналы продаж → CRM-формы → «Добавить»**, затем сценарий **«Обратная связь»** или **«Индивидуальная настройка»**. **[проверено]**
Слева настройки, справа предпросмотр. Название формы: `Заявка на подбор хостинга`.

При создании первой формы на бесплатном тарифе нужно подтвердить телефон по СМС (см. `BUILD_MAP.md`, шаг 0). Код вводите только в окне Битрикс24.

## 2. Какой элемент CRM создаёт форма

Раздел **«Сущности в CRM»** **[проверено]**:

- Если в вашем CRM включены **лиды**, выберите **«Лид»** и используйте **только поля карточки лида**. Если добавить поля контакта, данные уйдут в контакт и создастся повторный лид. **[проверено]**
- Если лидов нет (простой режим CRM), выберите **«Сделка + клиент»**. Тогда поля-списки из п. 3 создайте в карточке **сделки**.

Дубликаты: «Экспертная настройка» → «Разрешить дубликаты». Так каждая тестовая заявка будет отдельной записью. **[проверено: варианты настройки]**

## 3. Подготовить поля-списки (один раз)

Штатных полей «Направление» и «Вариант размещения» в CRM нет. Создайте их как пользовательские поля типа **«Список»** в карточке лида (или сделки): откройте любую карточку → **«Создать поле»** → тип **«Список»**. **[проверено: создание поля; где добавлять варианты списка — проверить на месте]**

| Поле | Тип | Варианты |
| --- | --- | --- |
| Направление | Список | Minecraft · Другая игра · Бот · Сайт или приложение · VPS · Нужна помощь с выбором |
| Вариант размещения | Список | Доступный старт · Повышенная производительность · Индивидуальная конфигурация · Пока не знаю |

**Запасной вариант**, если список создать не удаётся: уберите эти два поля из формы, а в подсказку к «Описанию задачи» допишите: «Укажите направление (Minecraft, другая игра, бот, сайт/приложение, VPS) и, если знаете, вариант размещения». Это ограничение нужно отметить в отчёте.

## 4. Поля формы (в таком порядке)

| Поле в форме | Поле CRM | Обязательное | Подсказка / настройки |
| --- | --- | --- | --- |
| Имя | Имя | Нет | «Можно указать псевдоним» |
| Email | E-mail | **Да** | Штатная проверка формата email |
| Направление | Направление (список) | **Да** | — |
| Вариант размещения | Вариант размещения (список) | Нет | — |
| Описание задачи | Комментарий (многострочный текст) | **Да** | «Например: Minecraft с модами, Telegram-бот на Python или небольшой сайт с базой данных» |

Для каждого поля можно задать обязательность, подсказку и значение по умолчанию, порядок меняется перетаскиванием. **[проверено]** Значения по умолчанию **не ставьте**.

**Телефон не добавляйте**: по ТЗ он не нужен.

## 5. Соглашение (согласие на обработку данных)

Раздел **«Соглашения»** → добавить чекбокс → **создать новое соглашение**. **[проверено: раздел; типы соглашений и их поля — проверить на месте]**

- Название: `Обработка данных формы`
- Если можно выбрать тип **«Свой текст»**, вставьте:

> Отправляя форму, вы передаёте указанные в ней данные (имя или псевдоним, email, выбранное направление и описание задачи) автору этой учебной работы. Данные используются только для ответа на обращение и демонстрации работы формы в рамках лабораторной работы. Они хранятся в закрытой CRM автора и не публикуются на сайте, не передаются третьим лицам и не используются для рекламных рассылок. Оплата и оформление хостинга через этот сайт не производятся. Чтобы удалить свои данные, напишите об этом в новой заявке через эту же форму.

- Если доступен только типовой шаблон с реквизитами организации, **не выдумывайте реквизиты**. Укажите только реальные данные: «оператор — автор учебной работы (физическое лицо)», цель — «ответ на обращение и демонстрация формы». Поля, которые нельзя заполнить правдиво, оставьте пустыми. Если шаблон требует их обязательно, переключитесь на «Свой текст».
- Галочка **не должна быть отмечена заранее**. Проверьте это в предпросмотре формы.
- Согласие на рекламную рассылку **не добавляйте**.

## 6. Кнопка и действия после отправки

| Настройка | Значение |
| --- | --- |
| Текст кнопки | **Отправить заявку** |
| Действие после отправки | **Сообщение** **[проверено]** |
| Сообщение при успехе | **Заявка получена.** |
| Сообщение при ошибке | Не удалось отправить заявку. Проверьте подключение к интернету и попробуйте ещё раз. |

## 7. Чего не включать

- СМС-уведомления клиенту, email-рассылки, автоответы на чужие адреса, роботов с платными действиями.
- Отображение заявок на сайте.
- Оплату и любые платные функции.

Уведомление о новой заявке внутри Битрикс24 (колокольчик ответственному) допустимо, оно бесплатное.

## 8. Тест формы (на опубликованном сайте, в окне инкогнито)

1. **Пустая форма** → «Отправить заявку». Ожидание: отправка не происходит, обязательные поля подсвечены.
2. **Email `test@` или `abc`** при остальных заполненных полях. Ожидание: ошибка формата email.
3. **Корректная заявка:**
   - Имя: `Тест`
   - Email: **ваш собственный адрес** (чужие и случайные адреса не используйте)
   - Направление: `Minecraft`
   - Вариант: `Доступный старт`
   - Описание: `LAB1-TEST-ГГГГММДД-ЧЧММ`, где подставлено **фактическое время отправки**, например `LAB1-TEST-20261008-1530`
   - Галочка согласия: отметить вручную.
   - Ожидание: сообщение **«Заявка получена.»**
4. **Найдите заявку в CRM:** CRM → Лиды (или Сделки) → поиск по `LAB1-TEST`. Сверьте все поля с отправленными значениями. Только это доказывает доставку: одно сообщение «Заявка получена.» её не подтверждает.
5. Для отчёта сделайте скриншот карточки, **замазав email**.

Если форма перестала работать, справка предлагает открыть `https://<адрес_вашего_Битрикс24>/crm/webform/?rebuildAll=y`. Настройки форм при этом не меняются. **[проверено]**
